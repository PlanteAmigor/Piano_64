# piano64_3 —— 四音色乐器、曲谱播放与教学（Tang Mega 138K）

2026-11-04：当前主分支为用户确认画面、按键与声音正常的 **720p低延迟完整版本**，Flash已写入并100%读回校验。显示为1280×720、约60.606Hz；三页面、下落音符、多乐器教学、蓝牙v3收谱与SD自动保存均保留。按下消抖0.5ms、松开确认20ms，18个数字链路场景最慢2.794ms（不含模拟音频输出延迟）。详见[720p低延迟固化交付](doc/720p_低延迟固化交付.md)。1080p60在独立实验分支继续排查，之前的候选时序通过但实机无信号，尚未作为正式固件验收。

用户只需按七个音级键及做手势，主旋律的乐器和八度由曲谱指定，其他声部自动伴奏。使用方法见[多乐器教学与显示说明](doc/1080p_多乐器教学.md)和[曲谱播放与教学说明](doc/曲谱教学模式设计.md)。

蓝牙 v3 收谱与自动存卡说明：[蓝牙收谱与SD保存](doc/bluetooth/蓝牙收谱与SD保存.md)。新功能回归：`python3 tools/check_bt_store.py`。

完整版本使用 `./build_full.sh` 构建、`./flash.sh --check` 校验、`./flash.sh` 临时下载；输出为 `impl/pnr/piano64_full.fs`。回归执行 `python3 tools/check_all.py --ui`。SD 卡需放真实 `P64.BIN` 和 `SONGxx.BIN`。

教学模式在节拍点以半力度兜底，±150 ms 内按对恢复正常力度，迟到匹配不重新触发音头。第一排前七键固定为 C D E F G A B。

以下保留早期钢琴原型资料，按键数量、旧指导曲目、`build.tcl` 和 `piano64.gprj` 均不代表当前完整版本；请使用上面的完整构建入口。

## 早期钢琴原型资料

> 纯硬件实时加法合成。每个采样点都是 FPGA 现场用 **64 个正弦分量**累加算出，**没有预录任何 PCM**。

---

## 这是什么

一块 **Sipeed Tang Mega 138K**（Gowin GW5AST-138）上的实时乐器：

| 功能 | 说明 |
|---|---|
| **7 个按键** | `KEY[0..5]` = do re mi fa sol la，`KEY[6]` = 模式键 |
| **64 路加法分量** | 每个音由 64 个指数衰减正弦叠加（赛题要求 ≥32，我们是 2 倍）|
| **4 声部复音** | 同时按 4 个键，全忙时抢最老的 |
| **3 个模式** | 1=按键发声 2=指导·小星星 3=指导·欢乐颂 |
| **WS2812 指示** | 按键灯 / 乐器灯 / 模式灯 / 指导目标灯 |
| **I2S 输出** | 到外置 PCM5102A，48.828 kHz / 16 bit |

## 快速上手

### 烧录

```bash
cd piano64
./flash.sh        # 下到 SRAM（掉电丢，调试用）
./flash.sh -f     # 固化到 Flash（掉电不丢）
```

### 重新构建

```bash
# Gowin EDA 装在本机 /mnt/project/ov-cli/Gowin（无需 license，实测可完整跑完 PnR）
export LD_LIBRARY_PATH=/mnt/project/ov-cli/Gowin/IDE/lib
export QT_QPA_PLATFORM=xcb
/mnt/project/ov-cli/Gowin/IDE/bin/gw_sh build.tcl
# 判据：ERROR 0 条（不要看 warning 数量）
# 产物：impl/pnr/piano64.fs
```

> 原交接文档里写的是 `../../bin/gw_sh build.tcl`，那是原作者机器上的路径，
> 本机不存在，已替换为上面的绝对路径。

### 重新生成参数表（可选）

参数表 `.hex` 已随仓库提交，一般不需要重跑。改分量数或换乐器时才需要：

```bash
export TMPDIR=$PWD/../../.tmp
PY=../../.venv/bin/python

# 古筝：先把 49 个单音 txt 合并，再生成表
$PY tools/merge_guzheng_txt.py \
    --dir ../../out/古筝_全音域/参数 --out ../../.tmp/guzheng_all.md
$PY tools/gen_modal_rom.py --table ../../.tmp/guzheng_all.md \
    --note-lo 38 --prefix gz_param --npart 128 --normalize 3000

# 钢琴
$PY tools/gen_modal_rom.py --table ../../out/piano/钢琴公式表.md \
    --note-lo 21 --prefix add_param --npart 128 --normalize 3000
```

`--npart` 决定每音取多少个模态（64 / 128 / 256），生成的表行数 = 音数 × npart。

### IDE 打开

```
Gowin IDE → File → Open Project → piano64.gprj
```

## 信号链

```
按键 ─► 消抖 ─► 复音分配 ─► 加法合成引擎 ─► 混音限幅 ─► I2S ─► DAC ─► 耳机
                          (64 分量/声部)
```

**数字域全在 FPGA 内部，模拟域只有 DAC 之后。**

---

## 核心数字

| 项 | 值 |
|---|---|
| 主时钟 | 50 MHz（V22，经 PLL 上全局网）|
| 采样率 fs | **48828.125 Hz** = 50 MHz ÷ 16 ÷ 64 |
| 每样点拍数 | **1024**（= 64 分量 × 16 流水级）|
| 位深 | 16 bit |
| 单音电平 | −12.5 dBFS（×4 增益后）|
| 4 音叠加 | −0.4 dBFS（刚好不削顶）|
| 按键延迟 | 82 µs（IMMEDIATE 消抖）|

> **关键等式**：`NPART × 流水线深度 = 1024` —— 这条约束决定了整套架构的所有取舍。

---

## 资源与时序

| 项 | 值 |
|---|---|
| Logic | 2785 / 138240（3%）|
| Register | 1866 / 139095（2%）|
| BSRAM | 56% |
| DSP | 14 / 298（5%）|
| **时序违例** | **48 条，最差 −10 ns** |

**⚠️ 时序违例是已知且接受的**：

- 路径全在 `add_voice` 的**包络通路**上
- 每 1024 拍才更新一次，偶尔错一次是样点幅度千分之一的偏差
- **实测听感无差异**
- 根因是 `1024 ÷ 64 = 16` 级流水线太浅，详见 `doc/分量数可行性分析.md`

## 硬件接线

### 音频（外置 PCM5102A 模块）

| PCM5102A | FPGA | J14 脚 |
|---|---|---|
| LCK | **P16** | 6 |
| DIN | **R18** | 8 |
| BCK | **V17** | 10 |
| VIN | 3V3 | — |
| GND | GND | — |

**模块侧跳线**：`SCK→GND`（用内部 PLL）、`FMT→GND`（I2S）、**`XSMT→3.3V`（不接就静音）**、`FLT/DEMP→GND`

### 按键

每个开关：一端接 J14 的 IO 脚，另一端接 **GND（J14 脚 12）**。片内上拉，不用外接电阻。

| 键 | J14 脚 | FPGA 球 | 音 |
|---|---|---|---|
| KEY[0] | 26 | AA20 | do (C4) |
| KEY[1] | 25 | AA21 | re (D4) |
| KEY[2] | 24 | AB21 | mi (E4) |
| KEY[3] | 23 | AB22 | fa (F4) |
| KEY[4] | 22 | Y21 | sol (G4) |
| KEY[5] | 21 | Y22 | la (A4) |
| KEY[6] | 40 | P14 | 模式键 |

### WS2812 灯带

| 灯带 | FPGA | J14 脚 |
|---|---|---|
| DIN | **T21** | 4 |
| VCC | 5V_Peripheral | 11（1.0 A 限流）|
| GND | GND | 12 |

**灯带布局**（⚠ 前 5 颗是坏灯，见下）

| 位置 | 索引 | 功能 |
|---|---|---|
| 第 1~5 颗 | 0~4 | 坏灯，保持黑 |
| 第 6~11 颗 | 5~10 | 6 个按键灯 |
| 第 12 颗 | 11 | 乐器灯（白 = 钢琴）|
| 第 13 颗 | 12 | 模式灯（红=1 / 绿=2 / 蓝=3）|

## 已知问题

### ① 灯带前 5 颗是坏灯

实测：从第 6 颗开始往后全部正常，前 5 颗有故障（该灭时乱亮、该亮时闪/偏色）。

**应对**：布局整体后移到索引 5 起，前 5 颗永远发 0。**建议换一条灯带。**

### ② 时序违例 1 条（I2S 输出）

实测（128 分量版）：25 条 setup 路径中只有 1 条违例，是 `u_tx/din_s0 → AUD_DIN`
的 **−0.085 ns**，与加法引擎无关。

加法引擎最差 slack 是 **+9.82 ns**（周期 20 ns），余量充足。

违例原因是 `piano64.sdc` 里 `set_output_delay -max 10.000` 定得过紧
（20 ns 周期只剩 10 ns 给外部）。**不影响听感，不需要修**；若要去掉，
改成 8 ns 或用 I/O 输出寄存器即可。

> 原交接文档说「48 条违例、最差 −10 ns、引擎路径 23 ns」，那是估算而非实测。
> 实际编译结果与此差异很大，详见 `doc/分量数可行性分析.md` 的勘误说明。

### ③ 音色库

工程里已带**两套** 128 分量参数表，通过 `src/add_top.v` 的
`TIMBRE_SEL` 常量切换（0 = 钢琴，1 = 古筝）：

| 音色 | 参数表 | 音域 | 分量 | 表深度 |
|---|---|---|---:|---:|
| 钢琴 | `add_param0/1/2.hex` | 88 音 MIDI 21–108 | 128 | 11264 |
| 古筝 | `gz_param0/1/2.hex` | 49 音 MIDI 38–86 | 128 | 6272 |

两张表不能同时装：钢琴 90 块 pROM + 古筝 33 块 = 123 块，加状态 RAM 后
接近 BSRAM 上限。一次编一个音色。

**下一步计划**：把多个音色表写进板载 W25Q64 Flash（剩 3.25 MB），
上电时读到 BSRAM，长按模式键切换。

**技术障碍**：
- `add_param_rom.v` 要改成**可写 RAM**（现在是只读 `$readmemh`）
- 新增 QSPI Flash 读模块（用配置完成后释放的 MSPI 脚）
- **笛子/唢呐是不同模型**（Φ/Ψ/Env 三张表 + 时变相位），当前引擎跑不了

### ④ ATK 起音项当前不可用

`add_voice8.v` 保留了起音上升项 `(1−e^(−t/τu))` 的逻辑，但参数表只存了 3 个
bank，`Rr` 被固定成 `25'd1`，起音速率实际没存。所以 `ATK` 必须为 0。
古筝的「铮铮」感需要这一项，将来要改用 4 bank 的表格式。

## 原理一句话

> **音色就是一张参数表（88 音 × 128 分量，每行存频率/衰减/幅度/相位）；
> 每个采样点都是 FPGA 现场用 128 个正弦分量累加算出来的 —— 没有预录任何 PCM。**

## 论文/答辩要点

| 赛题要求 | 实现 |
|---|---|
| 纯硬件实时合成，延迟 ≤10 ms | 按键到 I2S **82 µs** |
| 复音 ≥4 | **4 声部** |
| 单音分量 ≥32 | **128 路**（4 倍）|
| 严禁预录 PCM | 只存**参数**，每点实时计算 |
| ≥2 音色切换 | **2 套表已带**（钢琴/古筝），靠 `TIMBRE_SEL` 切换；Flash 在线切换待做 |
