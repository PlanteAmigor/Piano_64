| 项目 | 数值 |
|---|---|
| 分量数 | 88 音 × **128** 分量 |
| Logic | 2850 / 138240（**3%**） |
| Register | 1898 / 139095（2%） |
| CLS | 2048 / 69120（3%） |
| BSRAM | **114 / 340（34%）** |
| I/O | 13 / 297（5%） |

### 时序

| 类型 | 条数 | 最差 slack | 违例 |
|---|---:|---:|---:|
| SETUP | 25 | **−0.085 ns** | **1 条** |
| HOLD | 25 | −0.726 ns | 22 条 |

**最差 SETUP 路径**：`u_tx/din_s0 → AUD_DIN_obuf`
→ I2S 数据输出到引脚。当前 `src/piano64.sdc` 第 5 行是
`set_output_delay -clock CLOCK_50 -max 10.000 [get_ports {AUD_BCK AUD_LRCK AUD_DIN}]`
即 20 ns 周期里留 10 ns 给板外，内部只剩 10 ns。
PCM5102A 实际建立时间只有几 ns，这个约束**过紧**（不是内部逻辑问题）。
把 `-max 10.000` 放宽到 `8.000`（内部留 12 ns）即可清掉这条 −0.085 ns。

**最差 HOLD 路径**：`mode_1_s0 → u_led/n930 → u_led/sh_14_s1`
→ WS2812 移位寄存器。这类 hold 违例通常来自全局时钟网延迟估算偏保守，
**实测板上灯带工作正常**。但严格意义上未收敛，交接时需知悉。

## 三、每样点的时钟预算（谐波引擎）

一个音频样点 = **1024 个时钟**（50 MHz ÷ 16 ÷ 64 = 48828 Hz）

```
一样点 = 7 × NVOICE（前置） + Σ K_v（所有声部谐波总数） + 6（流水排空）
```

| 场景 | 实测拍数 | 预算 | 占用 |
|---|---:|---:|---:|
| 1 声部（最低音 K=62） | 74 | 1024 | 7% |
| 4 个不同音 | 205 | 1024 | 20% |
| **4 声部同音（最坏 K=62×4）** | **292** | 1024 | **29%** |

余量很大：理论上 Σ K_v 可以到 990，即 4 声部各 247 个谐波。
（实际笛子最多 62、唢呐最多 55，因为 K = ⌊24414/f₀⌋）
