
### 时钟域

```
CLOCK_50 (V22, 50 MHz)
   │
   ├──► pll50 ──► clk_sys (50 MHz, 全局时钟网)  ← 所有音频逻辑
   │
   └──► ws2812_keyind 直接接 CLOCK_50（无 PLL，避免 CDC 影响灯带）
```

**⚠️ 注意**：灯带模块时钟是 `CLOCK_50`，但它读的 `key_state`/`mode`/`guide_key` 是 `clk_sys` 域的跨时钟域信号。这两个时钟同频（都 50 MHz），信号变化很慢（按键级），实际无问题，但**理论上不是干净的 CDC**。

## 3. 逐模块说明

### 3.1 `add_top.v` — 顶层

**端口**

| 端口 | 位宽 | 说明 |
|---|---|---|
| `CLOCK_50` | 1 | V22，50 MHz 晶振 |
| `RESET_n` | 1 | AB13，低有效复位 |
| `KEY[6:0]` | 7 | **[0..5]=do~la，[6]=模式键**，低有效（片内上拉）|
| `AUD_BCK/LRCK/DIN` | 各 1 | I2S 到 PCM5102A |
| `DOUT` | 1 | WS2812 数据（T21）|

**关键参数**

```verilog
parameter integer STARTUP  = 2_500_000;   // 上电静音 50 ms
parameter integer DEBOUNCE = 1_000_000;   // 按键消隐窗 20 ms
```

**本模块做的事**

1. PLL 实例化 + 上电复位计数（`por_cnt` → `por_n`）
2. `key_scan`（N=7）→ `key_state/key_press/key_release`
3. **模式寄存器**：`mode` 1→2→3→1（`KEY[6]` 短按切换）
4. **曲谱表** `g_twinkle[0:41]`（42 音）、`g_ode[0:29]`（30 音）
5. **指导逻辑**：`guide_step` 按对才前进，`guide_key`/`guide_key2` 给灯带
6. `note_alloc`（NKEY=6, NVOICE=4）
7. `add_engine`（NPART=64、ROM_DEPTH=5632、NOTE_LO=21、NOTE_HI=108、ATK=0）
8. **输出增益 ×4**（`sat_gain` 函数，带饱和）
9. `ws2812_keyind` 灯带 + `pcm5102a_tx` I2S

**⚠️ 模式编号**：1=按键发声、2=指导小星星、3=指导欢乐颂。
（**注意**：这与老工程 `piano_twinkle_dac` 的编号不同，那个是 1=自动 2=按键 3=指导 4=指导）

### 3.2 `add_voice.v` — ★ 核心模块

整个项目最复杂的文件（~420 行），实现单声部 64 分量加法合成。

**端口**

| 端口 | 说明 |
|---|---|
| `note[6:0]` | MIDI 音号（装载时采样）|
| `trig` | 触发（一个时钟脉冲，重新装载）|
| `gate` | 1=按着（用 R1 衰减），0=松开（用 R_REL 快速释放）|
| `sample_tick` | 每帧一个脉冲（来自 `pcm5102a_tx`）|
| `sample[15:0]` | 输出样点 |
| `v_idle` | 1 = 没有分量在响（可用于抢声判断）|

**参数**

```verilog
parameter integer ROM_AW  = 13;     // 参数 ROM 地址宽度
parameter integer NPART   = 64;     // 分量数（★ 核心参数）
parameter integer NOTE_LO = 36;     // 音域下限
parameter integer NOTE_HI = 88;
parameter integer ATK     = 1;      // 起音项开关
parameter integer ROM_DEPTH = 1696;
```

**时间复用结构**

```verilog
wire [5:0] p = cnt[9:4];   // 第几个分量（0~63）
wire [3:0] s = cnt[3:0];   // 第几级流水（0~15）

// 每拍处理 (p, s) 这一个组合
// 1024 拍 = 64 分量 × 16 级
```

**16 级流水线**

| 级 | 动作 |
|---|---|
| s=0 | 读参数 ROM + 状态 RAM（`ph_q`/`e1_q`/`er_q`）|
| s=1 | `ph_n = ph + inc` |
| s=2 | 查正弦表 |
| s=3 | 再读一个点（插值准备）|
| s=4 | `ds = s1 - s0` |
| s=5 | `itp = ds × frac` |
| s=6 | `sv = s0 + itp` ← 波形值 |
| s=7~9 | 幅度混合（`amp1_r`/`amp2_r` 直通）|
| s=10~12 | `pr = sv × amp` |
| s=13 | `acc += pr` + 更新包络 |
| s=14 | 计算下一拍包络 |
| s=15 | 组装写回状态 RAM |

**状态 RAM**（每分量一组）

```verilog
reg [31:0] st_ph [0:NPART-1];   // 相位累加器
reg [31:0] st_e1 [0:NPART-1];   // 包络
reg [31:0] st_er [0:NPART-1];   // 起音包络（ATK=1 时用）
```

**装初值**（`trig` 时，等 `cnt==0` 再开始，避免横跨周期）

```verilog
ph  = phi8 << 24;      // 初始相位
env = a16 << 16;       // 初始幅度
```

**包络衰减**

```verilog
dec  = (env[31:8] × R1_eff + 0x800000) >> 24;
env  = env - dec;              // 指数衰减
R1_eff = gate ? R1 : R_REL;    // 松开时用固定快释放
```

### 3.3 `add_param_rom.v` — 参数表

**ROM 格式（3 bank，每行 3 × 32 位）**

| bank | 内容 |
|---|---|
| `d0` | `inc[31:0]` 相位增量 |
| `d1` | `R1[31:0]` 衰减系数（**32 位，不是 24**）|
| `d2` | `{a16[15:0], phi8[7:0], 8'b0}` |

**地址计算**（在 `add_voice.v` 里）

```verilog
wire [6:0] note_c = (note < NLO) ? NLO : (note > NHI) ? NHI : note;
wire [ROM_AW-1:0] rom_addr = { (note_c - NLO), p };
```

**两个模块**：`piano_param_rom`（DEPTH 5632）、`guzheng_param_rom`（DEPTH 3136），用 `generate` 按 `TIMBRE` 参数二选一。

**⚠️ 当前为只读 ROM**（`initial $readmemh`）—— 要做 Flash 现场加载必须改成可写 RAM。

### 3.4 `mix_sum.v` — 混音 + 软限幅

**5 级流水线**（比原来的 3 级多了 2 级，为了切断长路径）

| 级 | 动作 |
|---|---|
| 1 | `sum_r = 各声部之和` |
| 2 | `ax_r = |sum|`，`d_r = sum`，`sgn_r = 符号` |
| 3 | `d2_r = d_r × d_r`（乘法结果单独打拍）|
| 4 | 软限幅 `y = KNEE + (ax-KNEE)²>>16` |
| 5 | `out_v_r = 带符号输出`（打拍）|

**`tick_d[4]` 延迟链**对齐流水线，`sample_l/r` 在 `tick_d[4]` 时锁存。

**软限幅公式**

```verilog
KNEE = 24576  // 0.75 满刻度
if (ax <= KNEE)  mag = ax;
else             mag = KNEE + ((ax - KNEE)² >> 16);
```

---

### 3.5 `key_scan.v` — 按键消抖

**⚠️ 关键：低有效输入必须先取反**

```verilog
wire raw = ~key_in[g];        // 引脚有上拉：松开=高、按下=低，取反后按下=1
```

演奏键使用 `IMMEDIATE=0`：两级同步后，按下连续稳定 25,000 拍（0.5ms）、松开连续稳定 100,000 拍（2ms）才更新状态。短于门限的脉冲不改变状态。功能键保留 20ms 及菜单自身消抖；`IMMEDIATE=1` 仅保留旧功能键兼容行为，不用于演奏键。

旧文档的“第一边沿一定真实”和“82µs实测”不适用于当前完整硬件链路，已撤销。延迟应从原始输入到完整 I²S 非零样点测量；机械触点尚未稳定的时间及模拟 DAC/扬声器响应需单独实测。

### 3.6 `note_alloc.v` — 复音分配

已消抖按下每次仅分配一次，确认松开后立即重新使能，没有40ms/120ms重触发封锁。优先空闲声部，其次已松开的尾音，永不抢仍被按住的键。Gate在分配时立即占位，避免参数搬运期间idle仍高造成和弦覆盖。删除340ms余音禁用期；复用前先用旧参数平滑淡出，再允许DMA写新参数，防止换表造成阶跃。

### 3.7 `pcm5102a_tx.v` — I2S 发送器

**参数**

```verilog
parameter integer DIV   = 16;   // 每 BCK 的主时钟数
parameter integer SLOTS = 64;   // 每帧的 BCK 数
```

**频率**

```
BCK  = clk / DIV        = 3.125 MHz
LRCK = BCK / SLOTS      = 48828.125 Hz
```

**⚠️ 关键**：这是**唯一时钟域**，所有分频（BCK/LRCK/位索引/帧节拍）都从同一个计数器派生。**不要用 fabric 分频出的时钟去驱动逻辑**。

**⚠️ PCM5102A 与板载 PT8211 极性相反**：

| | 左声道 | 右声道 |
|---|---|---|
| PCM5102A | LRCK **低** | LRCK **高** |
| PT8211 | WS **高** | WS **低** |

本工程用的是外置 PCM5102A。

### 3.8 `ws2812_keyind.v` — 灯带指示

**参数**

```verilog
parameter integer N_LED       = 20;
parameter integer LED_BASE    = 10;   // KEY[0] 对应的灯索引
parameter integer NKEY        = 6;
parameter integer BRIGHT_SHIFT= 2;    // 1/4 亮度
parameter integer TIMBRE_LED  = 11;   // 乐器灯索引
parameter integer MODE_LED    = 12;   // 模式灯索引
parameter integer PRE_BITS    = 0;    // 帧首预留位数（当前 0）
```

**灯带布局（当前）**

| 位置 | 索引 | 功能 |
|---|---|---|
| 第 1~5 颗 | 0~4 | **坏灯，保持黑** |
| 第 6~11 颗 | 5~10 | 6 个按键灯 |
| 第 12 颗 | 11 | 乐器灯（白）|
| 第 13 颗 | 12 | 模式灯（红/绿/蓝）|
| 第 14~20 颗 | 13~19 | 空 |

**⚠️ 时序**（V6-2020 规格）

```verilog
T1H  = 33;   // 660 ns
T0H  = 17;   // 340 ns
TDUR = 65;   // 周期 1300 ns
TRST = 20_000; // 复位 400 µs
```

**⚠️ `dout_r` 必须寄存**：组合输出会在帧边界产生零宽毛刺，灯带会当成一位数据 → 整帧错位。

### 3.9 `pll50.v` — PLL 包装

```verilog
Gowin_PLL u_pll (
    .clkin   (clk_in),    // 50 MHz
    .init_clk(clk_in),
    .clkout0 (clk_out)    // 50 MHz（频率不变，只为上全局时钟网）
);
assign lock = 1'b1;
```

**⚠️ `lock` 是硬编码 1**：生成的 IP 没引出 lock 端口。上电复位靠 `por_cnt`（50 ms）兜住。

**为什么需要 PLL**：`CLOCK_50` = V22 是 **EMCCLK**（配置专用脚），不是 GCLK 引脚。直接用会走普通布线，实测时钟偏斜约 3 ns。过一级 PLL 才能上全局时钟网。

## 6. 已知问题与注意事项

### 6.1 时序违例（48 条，最差 −10 ns）

**原因**：`NPART × 流水线深度 = 1024` 是硬约束，64 分量时流水线只有 16 级，每级必须做完「ROM 读出 + 24×32 乘法 + 56 位加法」≈ 23 ns > 20 ns。

**路径**：`u_piano/g_voice[*].u_v` 的包络通路

**影响**：**听感无差异**。这些路径每 1024 拍才更新一次，偶尔算错是样点幅度千分之一偏差，被音乐掩蔽。

**详见** `doc/分量数可行性分析.md`

### 6.2 灯带前 5 颗是坏灯

实测：从第 6 颗开始往后全部正常，前 5 颗有故障（该灭时乱亮、该亮时闪/偏色）。

**应对**：布局整体后移到索引 5 起，前 5 颗永远发 0。

### 6.3 灯带时钟是 CLOCK_50 而非 clk_sys

```verilog
) u_led (
    .clk (CLOCK_50),      // ← 不是 clk_sys
```

跨时钟域读 `key_state`/`mode`/`guide_key`（都是慢变信号，实际无问题，但理论不干净）。

### 6.4 `ws2812_keys.v` 未使用

这是简化版灯带模块（无彩虹色轮），当前工程用的是 `ws2812_keyind.v`。保留作参考。

### 6.5 `PRE_BITS` 参数

`ws2812_keyind.v` 有 `PRE_BITS` 参数（帧首预留的 0 位），当前设为 **0**。
调试时曾发现某些灯带会「吃掉帧首 1 位」，那时设 1 能对齐 —— 但当前灯带不需要。

## 8. 代码阅读建议顺序

如果要理解这个工程，建议按这个顺序读：

1. **`doc/发声原理与算法.md`** —— 先懂数学原理
2. **`add_top.v`** —— 看信号怎么连起来（先跳过指导逻辑）
3. **`add_voice.v`** 的流水线部分 —— 理解时间复用
4. **`add_param_rom.v`** —— 理解参数表格式
5. **`mix_sum.v`** —— 混音和限幅
6. **`pcm5102a_tx.v`** —— I2S 时序
7. **剩下的辅助模块**（key_scan / note_alloc / ws2812_keyind）

**最容易看错的地方**：

- `add_voice.v` 里所有信号都是**流水线延迟对齐**的（`s=0` 读的数据，到 `s=6` 才用），改任何一级都要保证上下游同拍
- `add_param_rom.v` 是 `$readmemh` 初值 ROM，**不是**普通 reg 数组
- `key_scan.v` 的 `IMMEDIATE=1` 消隐逻辑（不是传统的"等稳定"）
- `ws2812_keyind.v` 的 `dout_r` 寄存是**必须的**，不能"优化掉"
