## 上板操作

1. FAT32 SD 卡根目录放置 **真实四音色 P64.BIN** 以及 `SONG01.BIN`～`SONG04.BIN`。交付包 `sd_card/` 已备好；不要使用 `work/song_checks/P64.BIN`，它只是 2048 字节仿真夹具。
2. 首次使用 SRAM 临时下载：在工程目录执行 `./flash.sh --check` 核对构建，再执行 `./flash.sh`。脚本使用 `impl/pnr/piano64_full.fs`，板型 `tangmega138k`。需要长期保存时自行执行 `./flash.sh -f`。
3. 等待原有 P64 加载与校验。按板上 KEY0，页面按 **主页面 → 测试 → 教学 → 主页面** 循环。
4. 教学列表中，**R1[8]（第一排第 9 键）短按下一首**；**R2[8]（第二排第 9 键）短按确认**。
5. 选中歌曲后，R1[8] 切换 AUTO PLAY / TEACHING；R2[8] 开始。运行时 R2[8] 停止；**长按 R2[8] 约 0.8 秒返回**。长按释放不再重复触发确认。切出教学页会停止歌曲。
6. TEACHING 有 3 秒准备时间。**第一排 R1[0..6] 固定对应 C D E F G A B**，与八度、原手动音色的键位映射无关；R1[7] 不参与教学判定。LED 提示音级，画面 `*` 表示需按，`+` 表示已匹配。

菜单 R1[8]/R2[8] 使用独立两级同步与双边 40 ms 消抖：按下、松开都必须连续稳定，短按在确认松开后只执行一次，持续按住不连发。演奏键仍沿用原扫描路径。`tb_song_keys` 用同一抖动波形复现旧版一次跳三首，并验证修复后一次一首、模式/确认不重复及长按返回释放抑制。

演奏键 R1[0..7] 使用两级输入同步和稳定电平模式：按下和松开都必须连续稳定 `DEBOUNCE`（默认 20 ms）才更新，避免单触点微动开关的松开抖动将一个按键变成虚假的松键/重按。实际音符键在全工程此前也已等待 20 ms 才确认按下；本修复将相同确认规则应用到松开，并为 `key_scan` 补上原来缺少的异步输入两级同步。`tb_key_scan_bounce` 对比旧版和修复版，检查旧扫描在释放抖动后产生假边沿/卡键，而新扫描每次真实按键只产生一个按下、一个松开。数字仿真覆盖的是同步后抖动行为，不能模拟真实模拟亚稳态或证明板上噪声的全部来源。

复音分配器的键归属增加一个可表示空闲标记的位宽，避免八键配置下 `KEY_FREE=7` 与真实键 R1[7] 冲突。旧版可复现第八键松开后 gate 仍保持高；`tb_note_alloc_release` 检查八键各分配一次、第八键独立松开及全部 gate 清零。

列表按照 FAT 枚举顺序显示文件本来的两位编号，不假定它们连续或按编号排序；最多 16 首、每页 8 首。精确匹配大写 `SONG00.BIN`～`SONG99.BIN`，不读子目录。

示例曲谱：SONG01《小星星》钢琴 47 事件；SONG02《茉莉花》古筝 30 事件；SONG03《小星星》唢呐 14 事件；SONG04《茉莉花》笛子 13 事件。

## 教学发声规则

- 到曲谱节拍时，即使没有手、没有按键，白键音符仍按**该事件正常力度的一半**准时起音，持续到各自曲谱结束。漏按不拖慢后续节拍，也不会因等待按键丢掉旋律。
- 在事件前 150 ms 内按对，对应起音使用正常力度；在事件后 150 ms 内按对，当前半力度声音按每毫秒增加 8/255 的速度恢复到正常力度，**不重新触发音头**。这些数值是引擎线性力度值，听感响度并非严格减半。
- 正常引擎力度为 MIDI velocity×2，兜底为 MIDI velocity；例如曲谱力度 100，对应正常 200、兜底 100。教学且有手时再叠加光学力度；自动模式不要求手参与。
- 同一时刻、同一音级的多八度和弦共享一次正确按键，各事件仍按独立时长结束；相邻重复音不能重用之前的提前按键。重叠判定窗口中的迟到按键优先对应最近已起音的一组。
- 已匹配的白键声部随对应物理键松开而释放；未匹配的半力度兜底保留曲谱时长。引擎原有自然包络、延音效果仍影响最终声音尾部。
- 黑键音符正常力度自动播放，不参与键盘判定。按错不会另触发声音；错误按键在匹配等待窗口结束后计数。
- 钢琴/古筝最多 8 声部；唢呐/笛子沿用原工程共享单音参数缓冲，限 1 声部。音高和音色由文件决定。

## 数据链路与接口

```
原有 P64.BIN → 原有 SD→DDR→读回校验
                         ↓ 成功后
SD 第二遍列目录 → SONGxx.BIN 字节流（晶振 50 MHz）
  → Gray 指针异步 FIFO → 帧解析/校验（音频 50 MHz）
  → 2048×64 事件 RAM → 毫秒调度/教学判定 → 原音频引擎
  → 原子状态快照握手 → HDMI 75 MHz 教学页
```

SONG 字节不进入 DDR 音色镜像写入 FIFO。文件结束后，必须排空跨域 FIFO、解析 FIFO 和帧状态机，再提交可播放结果，防止 END 尚未处理就开始播放。每次新文件重置解析事务；加载取消后继续排空旧传输，再允许下一次请求。

事件 RAM 131,072 bit，目标占 8 块 BSRAM；完整链路还有解析和跨域 FIFO。不要把整机资源增量都算成事件 RAM。保持原异步时钟约束，没有通过给新增同步路径设假路径消除违例。

v3 帧：`A5 5A 03 | type:u8 | seq:u8 | payload_len:u16LE | payload | crc16:u16LE`。CRC16/CCITT-FALSE 覆盖帧头到 payload，poly=0x1021，init=0xFFFF。

- BEGIN(type=1)：`count:u16, duration_ms:u32, timbre:u8, flags:u8`，flags 使用 0。
- DATA(type=2)：`offset:u16` 后跟最多 32 条事件。
- 事件：`start_ms:u32, note:u8, duration_ms:u16, velocity:u8`，共 8 字节，全小端。
- END(type=3)：`count:u16`；实际写入数必须与 BEGIN/END 一致。
- 最大 2048 事件，按开始时间非递减排列，时长非零，力度 1..127。必须符合对应音色音域和并发上限。错误不允许提交成可播放曲谱。

## 现场验收剩余项

- 用真实 SD 卡冷启动，确认四音色镜像校验、第二遍目录和四首曲谱均能读取；交换文件写入顺序再验证编号正确。
- SRAM 下载本包固件，听 SONG01 开头四声部和弦厚度；确认无手也发声，停止/返回/切页不遗留持续音。
- 教学模式听提前、迟到、完全漏按、错按、黑键，确认半力度兜底与恢复没有重复音头；检查光学表情和按键/LED 对应。
- 使用耳机或示波器测量实际键控到音频输出延迟与异常噪声；仿真和时序通过不替代赛题要求的现场测量。

参考沿用工作区 `ref/bt36_v3` 协议/调度器、`ref/FPGA-SDcard-Reader` 读卡栈、现有 Gray 指针 FIFO 与赛题要求；未额外引入可综合 IP 依赖。SDHC 仿真使用同一开源项目的 `sd_fake.v`，位于 `sim/vendor/`，随附原 GPLv3 许可。原有手动工程中的用户未提交注释空格改动已保留。


### 笛子 / 唢呐长按持续发声

- 保留约 1 秒的原始起音，然后固定稳态包络和残差相位；载波相位仍逐样点累加，继续响应弯音和手势颤音。长按不重触发、不重新搬运 DDR 表。
- 移除 5 秒绝对停音上限；手动按键和曲谱均由 gate 决定时长。松键默认收音，开启延音时仍按原释放增益淡出；手离开仍经原手势闸门静音。
- 独立 29 位 dm 相位时钟，模 2^29 回绕。由于 dm 为整数，dm×11×2^29/1024 是整圈相位，回绕无相位突跳，避免长按约 21 秒时旧 20 位时间计数器溢出。
- `sim/tb_harm_hold.v` 读取真实 P64.BIN，经实际 DMA 和谐波流水线检查全部 53 音的稳态转接、持续非零 PCM、相位运行、弯音、时钟回绕、手离开/返回以及 gate 释放。为缩短仿真，跳过起音前段与每样点计算完成后的空闲时钟，并把独立相位时钟推进到 10 秒；并非逐时钟完整模拟 10 秒。听感仍需上板验收。

- 加强 PCM 正负半周检查后，旧谐波编号错误在笛子 MIDI 76 暴露：表索引 0 被直接当作谐波阶数 0。原始拟合与渲染模型（上级 `tools/harm_fit.py`、`tools/dizi_render.py`）使用 1..K。引擎现将合成阶数改为表索引 + 1，HDMI 分量显示索引仍为 0..K-1，避免基音被合成为近直流分量。
