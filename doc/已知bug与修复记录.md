# 已知 bug 与修复记录

日期：2026-10-25
适用于：`main` 分支，`时序清零` 之后的提交

**TL;DR：128 分量钢琴引擎有 2 个 bug，都已修复并验证（与浮点理想波形相关系数 0.9947）。
另把 `sat_gain` 从 ×4 改成 ×8，用满动态范围且最坏情况不削顶。**

---

## ★ BUG-1：128 分量钢琴引擎输出噪声（已修）

**症状**：`add_engine8`（NPART=128, TIMBRE=0）触发任意音，输出不是钢琴音，
而是满幅乱跳的噪声。实测峰值顶到削顶，与理想波形相关系数 ≈ 0。

### 真实根因（**不是**相位错开/装载错位）

`add_voice8.v` 的 s==7 一级里，`e1n` / `ern` 用**非阻塞赋值**产生，
**同一拍**又被 `st_w1` / `st_wr` 采样：

```verilog
3'd7: begin
    e1n <= e1_q - dec1;        // 本拍才更新
    ...
    st_w1 <= e1n;              // 同一拍读 → 拿到【上一个分量】的值
    st_wr <= ern;
end
```

后果：状态 RAM 的回写整整**晚一个分量**，于是每播放一个样点，
幅度就在槽位间轮转 +1。每个分量的包络每个样点都在跳 → 听起来就是噪声。

**为什么 64 分量版没问题**：旧 `add_voice.v` 是 16 级流水，
`s=14: e1n <= e1_q - dec1` → `s=15: st_w1 <= e1n`，中间隔了一级，
所以一直是对的。这次压成 8 级流水时把这两步并进了同一级，才引入该 bug。

### 修复

直接使用当拍的组合值，不再经过同拍赋值的中间寄存器（`add_voice8.v` s==7）：

```verilog
st_w1 <= e1_q - dec1;                                       // e1_q 当拍有效，dec1 在 s=5 已打拍
st_wr <= ATK ? (er_q + {5'b0, dcdr}) : 32'hFFFF_FFFF;        // dcdr 是 er_q 的组合函数
```

顺带删掉了 `e1n` / `ern` 两个寄存器（−130 个 FF）。

### 验证（`sim/tb_engine8_chk.v`）

监听装载期与播放期的每一次状态 RAM 写操作：

| 检查项 | 修复前 | 修复后 |
|---|---|---|
| 装载后 `st_e1[k]` vs 表 row k | 完全一致 | 完全一致 |
| 播放 1 个样点后槽位错位 | **128 / 128**（整体 +1） | **0 / 128** |
| 输出波形 | 乱跳（-369→4146→7982→-3118…） | 平滑（-8313→-6515→-4294→-1827→714→3211…） |
| 峰值（MIX_SHIFT=1） | 顶到 16383（削顶） | 11459，不削顶 |

时序不受影响：重建后 SETUP 0 违例 / 最差 +9.563 ns，HOLD 0 违例 / 最差 +0.228 ns。

## ★ BUG-2：每个分量用了「邻居」的正弦值（已修）

**症状**：修完 BUG-1 后波形变平滑了，但与浮点理想模型的相关系数只有 **0.13**，
而且峰值虚高到 11459（1 万 1），音高也不对（自相关峰在 1878 Hz，而主导模态是 1571 Hz）。

### 真实根因

正弦表 `add_sine_lut` 是**同步读**（地址打一拍、数据下一拍出）。`add_voice8` 的时序是：

```verilog
3'd1: laddr <= (ph_q + rd0) >> 22;   // 本拍才给地址
3'd2: sw_r <= sw_raw;                // ← 多打了一拍，此时 dout 还是【上一分量】的
3'd3: ds <= sw_r[31:16] - sw_r[15:0]; // 用到的就是邻居的正弦值
```

`s==1` 给的地址在 `s==3` 这拍才出现在 `dout` 上，所以在 `s==2` 采 `sw_r` 采到的是
`s==1` 那拍地址（= **上一个分量**的 `laddr`）对应的值。

**实测铁证**（note 60, p=0）：

| 项 | 值 |
|---|---|
| `s==2` 的 `laddr` | 960 → 应为 `sin(337.5°) = −12541` |
| `s==3` 的 `sw_r` 低 16 位 | **27245** = `sin(56.25°)` = **索引 160** |
| 160 是哪来的 | 正是上一个分量 p=127 在它 `s==1` 时的 `laddr` |

后果：每个分量都在用邻位的频率 → 音高、音色全错，而且各分量相位不再抵消，
幅值虚高约 14 倍（11459 vs 修好后的 655）。

### 修复

`s==3` 直接用 LUT 当拍输出 `sw_raw`，删掉 `sw_r`（−128 个 FF）：

```verilog
3'd2: begin end       // laddr 这拍送到正弦表，下一拍输出有效
3'd3: begin
    ds  <= $signed(sw_raw[31:16]) - $signed(sw_raw[15:0]);
    fr  <= ph_n[21:12];
    sv0 <= $signed(sw_raw[15:0]);
end
```

### 验证

| 检查项 | 修复前 | 修复后 |
|---|---|---|
| 与浮点理想波形相关系数 | 0.13 | **0.9947**（最佳对齐 off=0） |
| 最佳拟合增益 | 1.20（拟合得很勉强） | **0.482 ≈ 1/2**（正好是 `MIX_SHIFT=1` 的 ÷2） |
| 峰值（note 60, `MIX_SHIFT=1`） | 11459（虚高） | **655**（模型预测 672 ✓） |
| 自相关主峰 | lag 26（1878 Hz，错） | 与主导模态 1571 Hz 一致 |

相关系数 0.995 / 增益精确 0.48 — 说明 RTL 的算术、定标、相位全部对上了。

## ✔ “定标”问题：虚惊一场（最终结论）

BUG-2 刚修完时我先报了一个「单音峰值比 1951 的目标小 3 倍 / 早先又大 6 倍」的问题，
**那个判断是错的**。用浮点模型扫全部音域后：

| 参数表 | `sample_l` 单音峰值（最大 / 中位） |
|---|---|
| 旧 64 分量表（上板验证过） | 1020 / 956 |
| 新 128 分量表（当前） | **817 / 615** |

两者同一量级（差 2~4 dB），说明**新表定标没跑偏，不需要重新生成**。
之前看到的 11459 完全是 BUG-2 造成的虚假幅值。

`add_top.v` 注释里的 1951 是更早一版表的实测值，不应再用作基准。

### 真正需要重算的是 `sat_gain`（已改）

按【最坏同相 4 声部】重新定标：

- 单声部 raw 峰值 `V = 817×2 = 1634`（×2 是补回 `MIX_SHIFT=1` 的 ÷2）
- 最坏同相：`Σ = 4V = 6536` → mix_sum 的 `>>1` → `3268`
- 要接近满刻度：`3268 × G ≤ 32767` → **G = 8**（2 的幂）→ 26144 = **−2.0 dBFS**

| `sat_gain` | 最坏同相 4 声部 | 实测典型 4 声部 | 判定 |
|---|---:|---:|---|
| ×4（原值） | 13072（−8.0 dBFS） | 7064 | 浪费 8 dB 动态范围 |
| **×8（新值）** | **26144（−2.0 dBFS）** | **14128（−7.3 dBFS）** | **✓ 不削顶，用满量程** |
| ×16 | 52288（+4.1 dBFS） | 28256 | ✗ 削顶 |

单音：`817×8 = 6536 = −14.0 dBFS`；古筝更轻（最大 324），安全。

实测 4 声部（MIDI 38/60/72/84）：引擎输出峰值 1766，**0 个削顶样点**。

## ✅ 已澄清：不存在的 bug

| 曾被怀疑的现象 | 实测结论 |
|---|---|
| 「状态 RAM 里包络与表错位 2 个分量」 | **不存在**。装载期写入序列 slot k ← 表 row k，127/127 全对；`PH_SHIFT = 2` 只影响时序相位，不参与装载 |
| 「4 声部相位错开与装载对齐冲突」 | **不存在**。4 个声部只错开 `s` 的相位，`p` 序列完全相同，ROM 广播靠「任意时刻至多一个声部在 s==0 / s==1」保证正确 |
| 「`add_sine_lut` 延迟不对」 | **不存在**。i=256 → 32767，确认是 Q15 sin 表；插值 `ds×fr` 与逐分量手算一致 |

## 复数后的教训（写进流程）

1. **改了流水线级数，必须重跑逐点仿真。** 这次把 16 级压到 8 级，
   把原来分开两级做的「算 e1n」和「写 st_w1」合并了，属于纯结构改动，
   综合和时序都完全正常，只有仿真能发现。
2. **不要只看「能综合、时序收敛」就当作功能完成。** 128 分量引擎
   之前只验证了编译和时序，`sim/` 里没有对应 testbench，
   所以这个 bug 一直没暴露。
3. **同一时钟沿赋值又读取的中间寄存器，是非阻塞赋值最容易埋的坑。**
   写 `x <= ...; y <= x;` 时，`y` 拿到的是**上一拍**的 `x`。
4. **同步读存储器（BSRAM/正弦表）的延迟必须数准。** 地址在第 N 拍给，
   数据在第 N+1 拍才出现在 dout 上；在第 N 拍就采样 `dout` 会拿到**上一次**
   地址的数据。这次两个 bug 都是「差一拍」，症状却完全不同：
   一个表现为噪声，一个表现为音高错误 + 幅值虚高。
5. **报「定标不对」之前先修完功能 bug。** 这次先误报了一次「响 6 倍」，
   其实是 BUG-2 让各分量相位不抵消造成的假象；修完后新旧表只差 2~4 dB。
