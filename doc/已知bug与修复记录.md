# 已知 bug 与修复记录

日期：2026-10-25
适用于：`main` 分支，`时序清零` 之后的提交

**TL;DR：128 分量钢琴引擎有 2 个 bug，都已修复并验证（与浮点理想波形相关系数 0.9947）。
另把 `sat_gain` 从 ×4 改成 ×8，用满动态范围且最坏情况不削顶。**

---

## ★ BUG-1：128 分量钢琴引擎输出噪声（已修）

**症状**：`add_engine8`（NPART=128, TIMBRE=0）触发任意音，输出不是钢琴音，
而是满幅乱跳的噪声。实测峰值顶到削顶，与理想波形相关系数 ≈ 0。

### 真实根因（**不是**相位错开/装载错位）

`add_voice8.v` 的 s==7 一级里，`e1n` / `ern` 用**非阻塞赋值**产生，
**同一拍**又被 `st_w1` / `st_wr` 采样：

```verilog
3'd7: begin
    e1n <= e1_q - dec1;        // 本拍才更新
    ...
    st_w1 <= e1n;              // 同一拍读 → 拿到【上一个分量】的值
    st_wr <= ern;
end
```

后果：状态 RAM 的回写整整**晚一个分量**，于是每播放一个样点，
幅度就在槽位间轮转 +1。每个分量的包络每个样点都在跳 → 听起来就是噪声。

**为什么 64 分量版没问题**：旧 `add_voice.v` 是 16 级流水，
`s=14: e1n <= e1_q - dec1` → `s=15: st_w1 <= e1n`，中间隔了一级，
所以一直是对的。这次压成 8 级流水时把这两步并进了同一级，才引入该 bug。

### 修复

直接使用当拍的组合值，不再经过同拍赋值的中间寄存器（`add_voice8.v` s==7）：

```verilog
st_w1 <= e1_q - dec1;                                       // e1_q 当拍有效，dec1 在 s=5 已打拍
st_wr <= ATK ? (er_q + {5'b0, dcdr}) : 32'hFFFF_FFFF;        // dcdr 是 er_q 的组合函数
```

顺带删掉了 `e1n` / `ern` 两个寄存器（−130 个 FF）。

### 验证（`sim/tb_engine8_chk.v`）

监听装载期与播放期的每一次状态 RAM 写操作：

| 检查项 | 修复前 | 修复后 |
|---|---|---|
| 装载后 `st_e1[k]` vs 表 row k | 完全一致 | 完全一致 |
| 播放 1 个样点后槽位错位 | **128 / 128**（整体 +1） | **0 / 128** |
| 输出波形 | 乱跳（-369→4146→7982→-3118…） | 平滑（-8313→-6515→-4294→-1827→714→3211…） |
| 峰值（MIX_SHIFT=1） | 顶到 16383（削顶） | 11459，不削顶 |

时序不受影响：重建后 SETUP 0 违例 / 最差 +9.563 ns，HOLD 0 违例 / 最差 +0.228 ns。

## ★ BUG-2：每个分量用了「邻居」的正弦值（已修）

**症状**：修完 BUG-1 后波形变平滑了，但与浮点理想模型的相关系数只有 **0.13**，
而且峰值虚高到 11459（1 万 1），音高也不对（自相关峰在 1878 Hz，而主导模态是 1571 Hz）。

### 真实根因

正弦表 `add_sine_lut` 是**同步读**（地址打一拍、数据下一拍出）。`add_voice8` 的时序是：

```verilog
3'd1: laddr <= (ph_q + rd0) >> 22;   // 本拍才给地址
3'd2: sw_r <= sw_raw;                // ← 多打了一拍，此时 dout 还是【上一分量】的
3'd3: ds <= sw_r[31:16] - sw_r[15:0]; // 用到的就是邻居的正弦值
```

`s==1` 给的地址在 `s==3` 这拍才出现在 `dout` 上，所以在 `s==2` 采 `sw_r` 采到的是
`s==1` 那拍地址（= **上一个分量**的 `laddr`）对应的值。

**实测铁证**（note 60, p=0）：

| 项 | 值 |
|---|---|
| `s==2` 的 `laddr` | 960 → 应为 `sin(337.5°) = −12541` |
| `s==3` 的 `sw_r` 低 16 位 | **27245** = `sin(56.25°)` = **索引 160** |
| 160 是哪来的 | 正是上一个分量 p=127 在它 `s==1` 时的 `laddr` |

后果：每个分量都在用邻位的频率 → 音高、音色全错，而且各分量相位不再抵消，
幅值虚高约 14 倍（11459 vs 修好后的 655）。

### 修复

`s==3` 直接用 LUT 当拍输出 `sw_raw`，删掉 `sw_r`（−128 个 FF）：

```verilog
3'd2: begin end       // laddr 这拍送到正弦表，下一拍输出有效
3'd3: begin
    ds  <= $signed(sw_raw[31:16]) - $signed(sw_raw[15:0]);
    fr  <= ph_n[21:12];
    sv0 <= $signed(sw_raw[15:0]);
end
```

### 验证

| 检查项 | 修复前 | 修复后 |
|---|---|---|
| 与浮点理想波形相关系数 | 0.13 | **0.9947**（最佳对齐 off=0） |
| 最佳拟合增益 | 1.20（拟合得很勉强） | **0.482 ≈ 1/2**（正好是 `MIX_SHIFT=1` 的 ÷2） |
| 峰值（note 60, `MIX_SHIFT=1`） | 11459（虚高） | **655**（模型预测 672 ✓） |
| 自相关主峰 | lag 26（1878 Hz，错） | 与主导模态 1571 Hz 一致 |

相关系数 0.995 / 增益精确 0.48 — 说明 RTL 的算术、定标、相位全部对上了。

## ✔ “定标”问题：虚惊一场（最终结论）

BUG-2 刚修完时我先报了一个「单音峰值比 1951 的目标小 3 倍 / 早先又大 6 倍」的问题，
**那个判断是错的**。用浮点模型扫全部音域后：

| 参数表 | `sample_l` 单音峰值（最大 / 中位） |
|---|---|
| 旧 64 分量表（上板验证过） | 1020 / 956 |
| 新 128 分量表（当前） | **817 / 615** |

两者同一量级（差 2~4 dB），说明**新表定标没跑偏，不需要重新生成**。
之前看到的 11459 完全是 BUG-2 造成的虚假幅值。

`add_top.v` 注释里的 1951 是更早一版表的实测值，不应再用作基准。

### 真正需要重算的是 `sat_gain`（已改）

按【最坏同相 4 声部】重新定标：

- 单声部 raw 峰值 `V = 817×2 = 1634`（×2 是补回 `MIX_SHIFT=1` 的 ÷2）
- 最坏同相：`Σ = 4V = 6536` → mix_sum 的 `>>1` → `3268`
- 要接近满刻度：`3268 × G ≤ 32767` → **G = 8**（2 的幂）→ 26144 = **−2.0 dBFS**

| `sat_gain` | 最坏同相 4 声部 | 实测典型 4 声部 | 判定 |
|---|---:|---:|---|
| ×4（原值） | 13072（−8.0 dBFS） | 7064 | 浪费 8 dB 动态范围 |
| **×8（新值）** | **26144（−2.0 dBFS）** | **14128（−7.3 dBFS）** | **✓ 不削顶，用满量程** |
| ×16 | 52288（+4.1 dBFS） | 28256 | ✗ 削顶 |

单音：`817×8 = 6536 = −14.0 dBFS`；古筝更轻（最大 324），安全。

实测 4 声部（MIDI 38/60/72/84）：引擎输出峰值 1766，**0 个削顶样点**。

## ✅ 已澄清：不存在的 bug

| 曾被怀疑的现象 | 实测结论 |
|---|---|
| 「状态 RAM 里包络与表错位 2 个分量」 | **不存在**。装载期写入序列 slot k ← 表 row k，127/127 全对；`PH_SHIFT = 2` 只影响时序相位，不参与装载 |
| 「4 声部相位错开与装载对齐冲突」 | **不存在**。4 个声部只错开 `s` 的相位，`p` 序列完全相同，ROM 广播靠「任意时刻至多一个声部在 s==0 / s==1」保证正确 |
| 「`add_sine_lut` 延迟不对」 | **不存在**。i=256 → 32767，确认是 Q15 sin 表；插值 `ds×fr` 与逐分量手算一致 |

## 复数后的教训（写进流程）

1. **改了流水线级数，必须重跑逐点仿真。** 这次把 16 级压到 8 级，
   把原来分开两级做的「算 e1n」和「写 st_w1」合并了，属于纯结构改动，
   综合和时序都完全正常，只有仿真能发现。
2. **不要只看「能综合、时序收敛」就当作功能完成。** 128 分量引擎
   之前只验证了编译和时序，`sim/` 里没有对应 testbench，
   所以这个 bug 一直没暴露。
3. **同一时钟沿赋值又读取的中间寄存器，是非阻塞赋值最容易埋的坑。**
   写 `x <= ...; y <= x;` 时，`y` 拿到的是**上一拍**的 `x`。
4. **同步读存储器（BSRAM/正弦表）的延迟必须数准。** 地址在第 N 拍给，
   数据在第 N+1 拍才出现在 dout 上；在第 N 拍就采样 `dout` 会拿到**上一次**
   地址的数据。这次两个 bug 都是「差一拍」，症状却完全不同：
   一个表现为噪声，一个表现为音高错误 + 幅值虚高。
5. **报「定标不对」之前先修完功能 bug。** 这次先误报了一次「响 6 倍」，
   其实是 BUG-2 让各分量相位不抵消造成的假象；修完后新旧表只差 2~4 dB。

# 唢呐引擎（`add_engine_harm`）调试记录

日期：2026-10-31
适用于：唢呐（`TIMBRE=3`）首次上板联调后的 4 个 bug

**TL;DR：唢呐「结尾嘟嘟」「音量偏大」「第 8 键松不开、力度反了」三个主诉，
根因分别是 ①Φ 表索引位宽截断 ②增益 ×8 进软限幅 ③gate/力度错用声部索引。
全部已修，3 秒全量仿真 + 上板确认。**

---

## ★ BUG-S1：Φ 表索引位宽截断 → 音符最后 15% 变「嘟嘟」噪音（已修）

**症状**：唢呐长按到 3 秒，从大约 **2.24 s** 起整段变成低频「嘟嘟 / 咕咕 / 放响屁」
的调制噪音；松键快停的键听不出来，只有长按到结尾才暴露。

### 定位过程（记录方法论）

1. 先看**参考素材**是不是也有：`out/suona/合成/AB_前后_M071_B4.wav`
   用基音周期（99 样点）做滑窗峰值包络，全程平滑，2.64 s 处直接归零。
   → **素材没问题，是 RTL 算错**。
2. 再用同样方法看 RTL dump（`harm_hw_dump.txt`）：

   | t (s) | 修复前包络 | 参考 wav |
   |---|---:|---:|
   | 2.180 | 1930 | 10388 |
   | 2.230 | **1953** | 10545 |
   | 2.281 | **130** ← 塌了 | 10873 |
   | 2.382 | **838** ← 乱跳 | 11430 |

3. 放大到 50 样点一块，看到 **t=2.2378 s 起 mean 从 −3 突跳到 −1089**
   —— 典型的「相位/参数突跳」，不是包络问题。
4. 反推时间：2.2385 s × 48828.125 = **109296 样点**。

### 根因

`add_engine_harm.v` 前置阶段（`pp==3`）：

```verilog
wire [63:0] cur_up = {32'd0, cur_ua} * (NT - 1);   // NT-1 = 599
...
v_px[hv] <= cur_up[40:32];       // ✗ 只取 9 位！
```

`cur_ua` 是 Q0.32 的 u（0→1），`u×599` 最大到 **599，需要 10 位**，
但只取了 `[40:32]` = **9 位（上限 511）**。

- `u×599` 首次越过 512 → `u = 512/599 = 0.85476`
- u 表下标 6831（`a_u = v_ts[19:4]`）→ **t = 109296 样点 = 2.2385 s**
- 实测崩点 2.2378–2.2398 s　→ **吻合到 1 个样点以内**

一旦回绕，Φ 索引从 511 掉回 0，Φ 曲线从头重放，`m·Φ` 相位全部错，
后 15% 就成了随机调制噪音。

### 修复

```verilog
v_px[hv] <= cur_up[41:32];       // ✓ 10 位，0..1023
```

`cur_ep`（NT3−1 = 149）取 `[39:32]` 8 位、`cur_pp`（NT2−1 = 299）取 `[40:32]` 9 位，
都够用，不用改。

### 验证（3 秒全量仿真，147000 样点）

| 检查项 | 修复前 | 修复后 |
|---|---|---|
| t=2.281 s 包络 | 130 | **1968** |
| t=2.332 s 包络 | 162 | **1971** |
| 音高（7 个采样点） | — | **493.21 Hz 恒定**，无一处跳变 |
| 结尾最后值 | 恒定 **15**（残留直流） | **0** |

## ★ BUG-S2：结尾衰减跑在 50 MHz 上 + 卡在 ±15（已修）

**症状**：音符结束（3 s 到期或松键）时「噗 / 嘟」一下；仿真里输出永久停在 15。

### 根因（两个独立错误叠在一起）

```verilog
if (!any_act && smp != 16'sd0)
    smp <= smp - (smp >>> 4);     // ✗
```

1. **没有 `cnt == 0` 门控**：这段写在 `always @(posedge clk)` 里，
   跑在 **50 MHz** 上。`smp` 本身每 1024 拍才更新一次（在 `ST_DRAIN`），
   所以「每 16 拍减 1/16」= **0.32 µs 就归零**，
   实际上等于「一个样点硬切」——还是有爆音。
2. **绝对值地板**：`|smp| < 16` 时 `smp >>> 4 == 0`，减不动，
   永远停在 ±15 → 输出**永久残留直流**（仿真实测就是 15）。

### 修复

```verilog
if (!any_act && smp != 16'sd0 && cnt == 10'd0) begin
    if      (smp >  16'sd32) smp <= smp - (smp >>> 6);
    else if (smp < -16'sd32) smp <= smp - (smp >>> 6);
    else                     smp <= 16'sd0;
end
```

- `cnt == 0` → 每个**样点**只衰减一次
- `>>> 6` → 时间常数 64 样点 ≈ 1.3 ms，降到听不见约 **6 ms**（既不爆音又够快停）
- 绝对值 ≤ 32 直接清 0 → 无残留直流

## ★ BUG-S3：唢呐第 8 键「松键不停 + 力度反了」（已修）

**症状**（用户实测，只有唢呐有，钢琴/古筝第 8 键正常）：

- 单独按第 8 键，**松开后不停**（拖尾很久）
- 第 8 键的**力度控制是反的**（轻按反而响）
- 但音高正确，且能被其他键打断

### 根因：gate / 力度用了 `note_alloc` 的**声部**索引

```verilog
wire sua_gate = is_suona && |v_gate;                     // ✗ 8 个声部"或"起来
if (v_trig[si]) sua_vel <= v_vel[si*8 +: 8];             // ✗ si 是声部号，不是键号
```

钢琴/古筝是**每声部一份状态**，按键 k 分配到声部 g 后 `v_gate[g]`/`v_vel[g]`
与按键一一对应，所以永远准。
但唢呐是**单声部**，要从 8 个声部里挑一个，于是：

| 现象 | 原因 |
|---|---|
| 松键不停 | `note_alloc` 是**轮转分配**，同一个键每次落在不同声部；只要任一残留声部 `v_gate=1`，`\|v_gate` 就永远是 1 |
| 力度反了 | `v_vel[触发声部]` 与真正发声的声部可能差一拍（轮转时序），取到别的音的力度 |

第 8 键最容易踩到，因为第 8 个键正好是轮转指针转满一圈的那个位。

### 修复：彻底绕开声部分配，直接看 8 个音源键

```verilog
wire sua_gate = is_suona && (|note_key_state);           // ✓ 任意音源键按住就发声
if (note_key_press[sv])                                  // ✓ 按键号索引
    sua_vel <= note_key_vel[sv*8 +: 8];
```

音高仍用 `v_trig` 那一拍的 `eng_note`（那个是准的），不动。

**★ 不要改 `note_alloc.v`**：其他乐器的 8 键一直是正常的，
问题只在于「唢呐是单声部却去借用 8 声部的状态」。

## ★ BUG-S4：唢呐「音量偏大」其实是 ×8 进了软限幅（已修）

**症状**：唢呐比其他乐器明显响，且带着一种压缩感。

### 根因

`sat_gain` 原来对唢呐也是 `<<< 3`（×8）。
引擎满力度峰值约 **7943~10000**，×8 = **63544~80000**，
远超软限幅膝点 24000，被压到 32192（压缩比约 **2.5:1**）
→ 波形被压成接近方波，RMS 反而更高，听感又响又「糊」。

### 修复

```verilog
y = (tb == 2'd2) ? (x <<< 1) :      // 唢呐 ×2 → 20000，在膝点以下，直通零失真
    tb          ? (x <<< 4) :       // 古筝 ×16
                  (x <<< 3);        // 钢琴 ×8
```

> ⚠️ 历史坑：更早有一次 ×8→×2 的编辑**静默丢失**（文件里还是 `<<< 3`），
> 导致之后所有「太响 / 嘟嘟」的反馈都还是在 ×8 下测的。
> 改完务必 `grep` 确认落盘。

## ★ BUG-S5：`sat_gain` 输出组合送 `u_tx` → SETUP −0.239 ns（已修）

**症状**：修完上面几个后综合报 SETUP 违例 −0.239 ns，
关键路径 `mix_l_r_4_s0 → … → u_tx/din`（24.097 ns > 23.858 ns）。

### 根因

`sat_gain` 是 function，里面有 `d*d`（16×16 乘法）+ 绝对值 + 膝点比较，
**组合**接到 `u_tx` 的 `sample_l/sample_r`，
而 `mix_l_r` 又是音频引擎输出级扇出最大的寄存器，布线很长。

### 修复

在 `sat_gain` 后面加一级寄存器，把「乘法–比较」和 `u_tx` 内部逻辑切开：

```verilog
reg signed [15:0] out_l_r, out_r_r;
always @(posedge clk_sys) begin
    out_l_r <= sat_gain(mix_l_r, timbre_r);
    out_r_r <= sat_gain(mix_r_r, timbre_r);
end
...
pcm5102a_tx u_tx ( .sample_l(out_l_r), .sample_r(out_r_r), ... );
```

代价：整体延迟多一个样点（20.5 µs），听不出来。

结果：**0 条时序违例**，最差 +0.020 ns；
Logic 20383（15%）、Register 16932（13%）、BSRAM 201（60%）、DSP 89.5（31%）。

## 唢呐调试的教训（写进流程）

1. **「结尾有怪声」先分辨是包络问题还是相位问题。**
   用**一个基音周期**做滑窗峰值包络，就能把「幅度在抖」和「波形本身粗糙」
   分开。参考素材本身就有 1290 处 >2000 的样点跳变，直接看波形只会误判。
2. **把「症状出现的时间」反算成样点号，再去代码里找对应的越界/回绕点。**
   这次 2.2385 s → 109296 样点 → `u×599 = 512` → 9 位截断，
   一条链走下来完全闭合，改一个位宽就修好了。
3. **`[N:M]` 切片宽度要用「最大值需要几位」倒推，不能凭感觉。**
   `599` 只要少取 1 位就是整个音符后 15% 报废，而综合、时序、功能仿真
   （如果只跑 2 秒）全都正常。
4. **`always @(posedge clk)` 里的「每样点」逻辑必须显式门控 `cnt == 0`。**
   这个模块是「一样点 1024 拍」的流水结构，忘了门控就是 1024 倍速。
5. **一阶衰减 `x - (x>>>k)` 一定要考虑 `|x| < 2^k` 的停滞区。**
   要么加绝对值地板清零，要么换成定点乘系数。
6. **单声部乐器不要复用多声部引擎的 `v_gate` / `v_vel`。**
   轮转分配下「声部号 ≠ 键号」，这类错误只在特定按键 + 特定时序下出现，
   极难复现（只在第 8 键暴露）。直接看音源键状态最稳。
7. **改增益前先确认上一个增益改动真的落盘了。**
   静默丢失的那次 ×2 让后面几轮反馈全建立在错误前提上。
8. **function 里带乘法的组合逻辑不要直接接跨模块端口，中间加一拍。**
   这次和之前的 `u_piano/u_mix → u_tx/din`（−0.853 ns）是同一类问题。
