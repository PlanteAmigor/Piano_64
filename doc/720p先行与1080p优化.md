# 720p 先行与 1080p 优化

先交付 1280×720、约 60.606 Hz 完整功能固件，之后独立优化 1920×1080 60Hz。蓝牙 v3 收谱、SD 自动存储与目录刷新、多乐器自动演奏、教学兜底、三页界面和音频修复在两个目标中共用。

720p 保留 1650×750 的行场总周期，恢复此前板上可用的单 PLL：75 MHz 像素时钟、375 MHz 串行时钟，刷新率约 60.606 Hz。先前精确 60 Hz 的两级 PLL 固件在板上 HDMI 无信号，已撤回；声音和灯正常，SRAM 同固件对照仍无信号，说明故障集中于显示链路，具体模拟时钟原因尚未实测确认。逻辑界面坐标仍为 1920×1080，以 3:2 采样输出，页面无裁剪。

切换：`python3 tools/set_video_mode.py 720p` 或 `python3 tools/set_video_mode.py 1080p`。工具同时修改 RTL 模式头文件和像素/串行时钟约束，随后必须 `./build_full.sh` 完整构建。烧录前 `./flash.sh --check` 核对源码、固件及全局 setup/hold 均通过。

本轮共用优化：播放器和预览共享同一事件数组，后续继续检查物理 RAM 推断；FAT 扇区缓存合并为单写口；文件长度计算分级寄存；SD 校验计数按字节并行计算进借位。这些改动保持文件格式和播放行为不变。

720p 烧录后，1080p 实验在独立源码快照进行，板上保持已验证的 720p 固件；只有新的完整时序通过后才替换。
