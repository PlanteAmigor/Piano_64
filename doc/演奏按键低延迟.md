# 演奏按键低延迟

目标：在有效手势已存在、P64 音源已装载的演奏状态，原始按键输入至 DAC 收到新音有效 I²S 数据字低于 5ms。720p 显示及原有教学、蓝牙、效果器功能保持。

## 实现

- `add_top` / `piano64_top` 新增 `PLAY_PRESS=25000`、`PLAY_RELEASE=1000000`，50MHz 下分别为 0.5ms / 20ms。演奏键为 R1[0..7]；R1[8]、R2、AUX 及菜单保留原有独立消抖。
- 输入先经过两级同步。按下与松开均须连续稳定，低于各自门限的脉冲不会产生状态变化；长按只触发一次。
- 删除顶层共享40ms按下脉冲屏蔽、分配器每键120ms锁定及声部340ms禁用期。确认松开即可重新按下。
- 分配即以gate保留声部；DMA装载前idle暂时为高也不能覆盖已分配声部，保证同时和弦不会落到同一个声部。
- 优先空闲声部，其次复用已松开的尾音；仍按住的声部不抢占。复用时先用旧参数淡出，`cache_safe`后才启动DMA换表，取表完成后装载并正常淡入。

## 可复现验证

```bash
python3 tools/check_all.py --bt
python3 tools/check_key_latency.py
python3 tools/check_key_latency.py --timbre 0 --effect 1
./build_full.sh
```

`tb_key_fast` 使用真实50MHz：499µs按下窄脉冲被拒绝，19.999ms松开窄脉冲被拒绝，带抖动八键只生成一组触发；十二次20.7ms间隔的重复和弦均完整，独立松开/重按第八键不会干扰其他键，最终gate全部清零。分配器的idle刻意保持为1，覆盖DMA前的占位问题。

`tb_key_latency` 直接实例化实际 `add_top`。保留分配、CDC、DDR仲裁、真实P64取表、音源起音/淡出/淡入、增益、限幅、效果器和I²S输出；只建模PLL与物理DDR。50/100MHz与48.828kHz采样率保持实际值，不快进音频时钟，不强制PCM，不跳过起音包络。

物理DDR模型包含周期性刷新背压，每笔返回等待64~72个100MHz时钟。以初次闭合为计时起点，首轮包含0.6ms触点抖动；另测快速同键、不同键、同时和弦及尾音复用。逐声部确认新参数已完成装载并产生非零PCM，然后独立解码实际BCK/LRCK/DIN，额外预留四个采样帧覆盖音频输出流水。因此报告值比新音第一次可能到达DAC更保守。

每次参数缓存写入均断言对应声部已经静音且`cache_safe=1`，防止旧包络配新参数。四音色日志与源码指纹位于 `work/key_latency/latency_*.json` / `.log`。

混响/延音测试使用已有 `SIM_INIT` 选项模拟上电存储器初始化，避免未装载参数中的仿真X污染空闲包络；音源参数仍由真实P64经DMA装入，没有预先装载测试音或替换输出。首轮未启用该选项的失败诊断留在work目录，不作为验收结果。

## 验收边界

这里验证的是数字链路；模拟DAC滤波、功放、扬声器及声传播延迟须用示波器或回录另测。手势已经有效是测试前提，首次移动手势的识别时间不属于此次按键延迟。

连续稳定确认不能保证任意持续时间的机械抖动均从第一跳起5ms内发声；真实触点持续多久仍需上板验证。更长抖动或超过DDR模型上界的服务等待均不可用本报告外推保证。正常确认松开约20ms，钢琴/古筝既有自然余音不等于松键失效。

完整构建须通过 `tools/check_build.py` 的源码/比特流一致性、全局setup/hold均零违例后才允许下载。先SRAM试听；保留之前断电启动通过的720p Flash回退。

## 实物反馈与第二版修正

第一版数字仿真18次均低于5ms，但用户反馈画面正常、按键或声音有异常（重复起音、爆音或松键不停），因此第一版实物验收失败，不再作为推荐固件。

补充的 `tb_key_release_chatter` 证明：物理按住期间只要出现4ms的断开回弹，第一版2ms释放确认会产生假的松开/重新按下。该波形是逻辑复现，尚未采集真实按键波形，不能据此断言已找出所有实物异常原因。第二版把释放恢复到先前已验证的20ms确认，按下仍为0.5ms。真实松开少于20ms的同键重按会合并，这是消抖门限的明确取舍；没有重新引入40/120ms的固定锁定。

第一版结果仅作历史记录：钢琴/混响最慢2.792ms，古筝2.690ms，唢呐1.871ms，笛子2.056ms。第二版须重新运行完整链路与回归，并重新综合、检查时序、上板试听，不能沿用第一版测量。

用户随后确认：恢复原稳定720p、以同样按法测试后，异常消失。该对照已记录于 `work/key_latency/revision2/baseline_user_confirmation.json`。第二版仍须独立实物验收。

加载后新鲜3秒串口窗口：有效光学数据0行，错误报码0行。该窗口只反映本次采样，不能把它等同声音验收。
